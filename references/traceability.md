# 阶段溯源记录

修改 PSD 或执行 Prefab 减法与布局时读取。每个界面长期维护一对固定的 UTF-8 Markdown 说明，记录素材来源、实际修改和决策依据；后续轮次只在原文件内追加，不另建一套说明、工程内脚本或独立台账。

## 存放与关联

首次建立链条时，使用目标项目允许的固定界面报告目录，保持在 Unity 导入范围之外。PLink 项目遵守现行 `.cursor/`，可使用 `AIArchive/reports/<面板名>/`。已有说明沿用实际路径，不因目录曾带任务编号而迁移或新建副本。固定的两个文件为：

- `01-PSD修改说明.md`，从 [PSD 修改说明模板](../templates/psd-change-record.md) 填写。
- `02-Prefab减法与布局说明.md`，从 [Prefab 减法与布局模板](../templates/prefab-adjustment-record.md) 填写。

模板和流程放个人 Skill，实际文件路径、图层、界面决策和验证结果放目标项目。项目内资源引用使用项目要求的相对路径；第二份说明可用同目录相对链接引用第一份。项目外源文件记录真实来源位置，避免把机器路径写入通用模板。

每次处理可用开始时间 `yyyyMMdd-HHmmss` 作为任务/记录编号，冲突时增加精度；编号用于文件内区分记录，不用于新建 MD。涉及两份说明时，用相同编号串联相应记录。第二份引用真正参与导出的 PSD 路径与 SHA-256，须对应第一份中被使用的那个输出版本（包括修订行）。摘要不一致时先查证并关联正确记录，不将同名文件视为同一版本；PSD 后续更新不能改写第二份既有导出事件使用的历史摘要。

源 PSD 的新一轮设计更新在同一对说明内追加记录块，关联文件内此前的记录编号，保留旧来源、输出和结论。用户修正 `_UI.psd` 时在同一份 `01-PSD修改说明.md` 追加修正与导出前检查；再次导出时在同一份第二说明追加导出事件及后续阶段，不覆盖旧事件的 PSD/Prefab 摘要。用户自行修正正式 Prefab 适配时，也在这同一份 `02-Prefab减法与布局说明.md` 追加时间、参数和验收结果。

第二份说明区分当前正式状态、待合并候选和历史事件，记录实际所属版本与状态，不因候选更新就把它写成正式生效。正式适配在候选等待期间变化时，修订仍写同一份第二说明，并更新受影响的候选比较依据；历史清单及确认记录保留，不复制到另一份 MD 各自维护。

## 记录时机

1. PSD 修改前建立或维护固定第一份说明，在本次记录中填写源文件信息、目标位置和计划变更；创建新工作副本后修改。保存并重新打开后，补齐实际变化、理由、输出 SHA-256 和源文件前后摘要。源文件未变且输出复核通过，才把相应检查标为通过。
2. 每次导出前执行 [整理稿检查](psd-preparation.md#导出前整理稿检查)，在第一份记录核验版本、人工修正和结果。导出后、后处理前建立或维护第二份，填写输入 PSD、现成工具菜单/按钮或其同一方法入口、实际 Importer、关键配置来源与已确认参数、工具实际输出路径、刚导出的 Prefab 指纹与原状。工具新写出、已有资源复用及明确获准的迁移分别记录，不能把迁移后的路径写成原始导出位置。源稿新一轮更新从源开始；本轮人工修正从修正版续作。已有正式 Prefab 时记录工具支持的隔离方式，生成临时 Prefab 与其比对，分别记录二者路径、摘要和历史基线。导入造成的字体替换或效果差异单独记录。
3. 减法与布局完成后填写实际操作、原因、关键参数、布局完成指纹及验证结果。原因要对应需求或源码依据；未确认用途写成假设或待确认，不因“当前没有调用”就断言不需要。
4. 绑定生成后先记录本次必要的手写引用修复，编译通过且刷新检查完成后，追加绑定完成指纹和引用检查结果，不覆盖布局完成指纹。修复或编译未通过时保留实际中断状态，不将“已生成代码”当成绑定完成；其余功能阶段再次改动 Prefab 时追加对应状态。

操作前的计划与操作后的结果明确区分。PSD 说明用于记录已授权的素材处理，不增加审批步骤；修改正式 Prefab 前，在第二份说明列齐本次变更、原因、对应功能代码影响及拟执行范围，让用户一次确认。Agent 判断需要重建时，明确说明理由、引用影响和重建方案，可放入同一清单确认；获得明确确认后才重建。确认范围内的代码实现继续执行，不重复询问。失败或中断如实记录，不将待执行项改成已完成。

清单保留其形成时的正式资产、候选及相关资源版本和关键字段证据。实际写入前按 [正式写入前复核](existing-ui-maintenance.md#正式写入前复核) 追加检查结果与保留的用户新修改，不能用当前摘要覆盖清单的旧比较依据。图片复用/更新说明包含内容与导入设置的判断依据、候选及正式资源落点和共享引用影响。

## 维护记录

- **PSD 变化**：记录源 PSD、临时导出和正式 Prefab 的比较结果。用户确认后合并；仅对新增或变化节点做减法与布局，保留正式 Prefab 既有适配，旧后处理不得直接覆盖用户参数。需要重建时沿用正式名称和路径，并检查原引用。
- **用户修正整理稿**：在原第一份追加修改图层、可核实的前后值、理由或“原因未说明”、当前版本及导出前检查证据。单页选择保留在此，可复用纠错按 [反馈生成规则](psd-preparation.md#反馈生成规则) 记录适用范围、规则落点与实施状态。指纹变化不证明具体修改项或作者；无旧证据时注明历史未知。
- **合并完成**：每次合并后调用现有绑定入口，按“生成→必要手写引用修复→编译通过→刷新”执行，记录面板、Item 及相关功能代码和引用检查结果。合并检查通过后删除临时 Prefab，记录清理结果；最终保留正式 Prefab，清理不得误删其依赖图片。
- **用户仅修改适配**：以当前正式 Prefab 为准，检查显示效果，在原第二份说明追加用户适配修订、实际参数和验证结果。不重新导出 PSD、不重放旧后处理、不重跑绑定。若检查发现还包含结构或绑定变化，按实际范围归入维护清单，不将其记录为纯适配修改。

## 范围与修订

- 只处理 PSD 时只建立或维护第一份；只做已有 Prefab 后处理时只建立或维护第二份，并引用已有 PSD 说明。没有可核实的历史记录时注明来源未追溯，不能补造前后指纹或历史验证。
- 仅修改手写功能且节点与绑定不变时，不新建 PSD/Prefab 说明或填写空的正式修改确认清单；按项目要求记录代码变更和验证，需要关联链条时可在原第二份追加功能修订。导出、生成和刷新标为本次不适用，不影响已有阶段的历史完成状态。
- 源 PSD 新一轮更新在固定说明内追加处理记录；同轮补充修改、整理稿人工修正和用户纯适配修订追加简短记录，保留曾被下一阶段使用的输出版本指纹。模板的来源、输出、清单和验收表属于对应记录块，后续记录不覆盖先前块中的事实。每次导出用时间或事件编号对应输入版本、候选、正式比较基线及后续阶段，不能将旧候选关联到新修正稿。只有另一个界面需要建立自己的固定说明。
- PSD 表只逐项记录变化图层；图层 ID 可辅助定位，但不当作跨文件永久标识。Prefab 表区分去绑定、删节点、模板选择和参数调整。
- 模板、外观参考与运行实例分别说明；删除参考并保留唯一模板不表示运行时数据和生命周期已实现。
- 指纹绑定到具体阶段和保存状态。布局表保留验收过的实际参数，用户后改参数追加新修订，不仅记录摘要。未保留二进制快照时，不声称仅凭说明或摘要就能还原所有旧版本；源 PSD 必须实际保留。
- 复用已有验证证据链接，不为填模板重复执行昂贵操作。分辨率预览、代码编译、引用检查和 PlayMode 分别写实际结果及未执行项。
