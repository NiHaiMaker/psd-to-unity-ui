# Prefab 精简与布局

源 PSD 更新须先完成 [源更新差异审核](psd-preparation.md#源更新先审核差异)，用户同意后才更新 `_UI` 并执行本阶段；该审核仅用于源 PSD 更新；首次生成、整理稿续作及纯适配等入口按各自授权执行。Prefab 生成后按当前说明对比、恢复仍适用减法并更新变化项，再生成代码。业务仅修复受影响旧逻辑或补全此前已实现功能的差异接入；此前未实现的功能不自动补全。

在视觉 Prefab 已生成、需要精简节点绑定、落实 Item 复用或配置适配布局时读取。此阶段处理运行资源；PSD 保留设计与外观参考，除非本次同时要求回写。优先配置 Unity 内置和项目既有组件，不为整理/适配新增自定义 MonoBehaviour、工程内辅助 `.cs` 或永久菜单。完整流程在此阶段完成后继续调用现有绑定生成，完成必要手写引用修复，再编译和刷新。

已有正式 Prefab 或用户适配修订时先读取 [已有链条维护](existing-ui-maintenance.md)：生成前核实旧正式资产并补齐当前两份说明的适配基线，按新建主流程生成后快速恢复仍适用配置、处理实际差异；已有明确授权不另设重建确认；用户仅改适配时只检查和记录，不适用本节完整重放和绑定顺序。

## 先精简运行职责

为待调整节点记录原定位、用途、保留的视觉、绑定变化及理由。已有面板先检查手写代码、动画和序列化引用；“当前没有显隐调用”不能证明节点无需动态内容或交互。

使用 [阶段溯源记录](traceability.md) 中的第二份模板，在重新生成前记录旧正式 Prefab 的可恢复位置、稳定节点定位、布局/组件参数及引用；生成后另记未经后处理的工具输出与调整意图，完成后填写实际变化、原因和验证。仅记录摘要不能支持恢复适配。布局完成及绑定刷新后的 Prefab 指纹分开保留，使说明能够对应具体资产状态。

| 节点职责 | 处理 |
|---|---|
| 始终显示的背景、边框、静态文字 | 保留视觉；无运行访问需求时去绑定标记 |
| 动态文字、图标、进度、点击目标 | 保留对应组件或交互绑定 |
| 纯锚点/布局容器 | 保留层级职责，无代码访问需求时不绑定 |
| 需要整体显隐、移动或播放状态的功能组 | 保留所需组引用；勿把独立控制需求误判为冗余 |
| 可由同一模板表达的重复结构 | 保留一个模板，明确实例数量、数据来源及生命周期 |

绑定精简不等于视觉删除。移除空容器前确认它不承担锚点、蒙版、布局、动画或组件引用，并验证子节点的坐标、缩放与绘制顺序。装饰 Graphic 的 Raycast Target 可在确认不承担点击命中后关闭；不能关掉唯一的交互命中面。

## 模板与实例

先比较字段、组件类型、布局和变化数据，结构不同的控件不强行合并。参考外观的切图、字体和文字需有保留或数据接入方案；只有替代实例方案明确后，才从最终运行 Prefab 移除参考节点。只交付 Prefab 时，可以保留唯一模板并说明显示实例的接入点，不虚构业务列表。

模板可以本身作为首个显示项，也可以隐藏后用于克隆。隐藏模板通常不参与 LayoutGroup 排列；克隆继承隐藏状态时必须显式激活。核对最终父节点、兄弟顺序及模板是否意外占位。运行生成器要求模板先完成 Mono 与引用刷新时，遵循其顺序，不能把普通参考节点当作已绑定实例。PLink 细节见 [通用 Item 判定](plink-integration.md#通用-item-判定)。

## 锚点与布局组件

先确定整体区域与屏幕边缘的关系，再安排区域内部的序列。固定 HUD 使用顶部/底部/侧边锚点；列表内部由布局组件排布，图标上叠加的冷却、文字和特效仍保持相对定位。

| 需求 | 选择与约束 |
|---|---|
| 同级元素从左到右或从上到下排列 | HorizontalLayoutGroup / VerticalLayoutGroup；按设计设置顺序、间距、Padding、Child Alignment |
| 单元需要固定或首选宽高 | LayoutElement；父组开启对应轴的 Child Control Size，按需关闭 Child Force Expand |
| 容器需随内容大小伸缩 | ContentSizeFitter，仅启用需要的轴；确认父布局没有同时控制该轴尺寸 |
| 装饰或模板需要排除出布局计算 | 按用途放到布局容器外、隐藏，或设置 LayoutElement.ignoreLayout；勿将显示实例一并排除 |

同一 RectTransform 的同一轴只由一个系统决定尺寸，位置也只由一个系统驱动。添加布局前检查运行脚本是否写 anchoredPosition/sizeDelta；移除或迁移冲突的控制，不让布局和脚本反复覆盖。固定区域不为“配齐组件”添加 ContentSizeFitter。需要缩放/脉冲效果时通常保持 Child Scale 关闭，或将效果放到单元内部的视觉子节点，避免相邻项随动画抖动。

布局组件无需代码绑定标记；存在明确运行访问需求时，才按项目支持方式暴露引用。参考尺寸、CanvasScaler、根 Canvas 与安全区服从现有运行框架：不要在嵌套 Canvas 上盲目添加第二套缩放或安全区控制。

## 文本居中与溢出

先按实际用途区分固定文本与动态文本，沿用当前的 UGUI Text 或 TextMeshProUGUI，不为检查而迁移组件：

- **固定文本不额外做防爆框处理。** 标题、固定按钮文案等内容不会变化时，按实际文案核对对齐和显示即可；不构造长文案测试，不额外增加自动缩字、换行或溢出策略。当前文案已经显示异常时，只修复实际问题。

- **按设计对齐。** 需要居中的标题、按钮文案等，同时核对文本 RectTransform 相对目标区域的位置、文字的水平/垂直对齐、内边距和行距。文本框居中不代表字形已经居中，居中锚点也不能替代文字对齐设置；原本左对齐或右对齐的内容保持设计意图。图标加文字的按钮按设计检查整组与文字各自的位置，不把文字单独强拉到按钮中心。
- **先核对可用空间。** 检查父级 LayoutGroup 的 Padding/Spacing、文本框实际宽高、LayoutElement 尺寸约束和 TMP Margin，确认字体映射、字号及字形实际渲染一致。修复落在 Prefab 的文本与布局配置中；不靠补空格、随意位置偏移或运行时改字号/样式来掩盖偏差，不新增适配辅助脚本。
- **动态文本按实际预期决定超长策略。** 依据业务已知的名称长度、数值范围、位数、单位或换行需求判断是否存在爆框风险，没有预期风险就不额外配置。存在风险时，单行内容检查横向空间，多行内容检查换行后的高度及对邻项的挤压。优先调整合理边距和可用空间，在设计允许时换行或让容器按既有布局规则伸展；沿用同一轴只有一个尺寸控制者的约束。确需缩小字号、Best Fit/Auto Size 或截断/省略时，按已确认设计配置，保留可读字号下限；关键数值、操作文案不得靠截断或蒙版隐藏问题，也不一律开启无限 Overflow。
- **检查最终渲染。** 在实际字体与布局重排完成后，观察文字的可见边界、上下留白、基线、遮罩/RectMask2D 裁切和与邻项的重叠；Text 的水平/垂直 Overflow 与 TMP 的换行、溢出、Auto Size 等配置按各自组件核实。Preferred Size 或属性值仅作辅助，不用“没有越出 RectTransform”替代文字完整显示的证据。
- **按用途选择验证样本。** 在基准尺寸及本次选定宽高比，固定文本使用实际文案；动态文本仅覆盖业务预期的内容范围，如最长名称、最大位数或确有需求的多行内容，多语言仅在需求包含时覆盖目标语言。动态内容替换后重新布局再检查对齐和已识别的溢出风险；预期范围不明时先查已有需求和代码依据，记录尚未确定项，不自行设定无限长度或为假设场景过度适配。临时预览用的测试文案验证后恢复，不写成正式默认内容。

把涉及的节点、固定/动态用途、实际预期、变化参数、采用原因和验证样本写进原 `02-Prefab减法与布局说明.md`；固定文本的动态防爆框项标为不适用。修改正式资产沿用已有授权范围，具体新冲突或范围扩张另行说明；用户已自行修正的适配按维护入口只检查和记录，不自动改回。

## 重导入与实际验证

涉及重新导出 PSD 时，先执行 [导出前整理稿检查](psd-preparation.md#导出前整理稿检查)，使用核验后的当前修正版，不能为重导入测试从源重生成来覆盖它。仅对已有 Prefab 重放后处理时不额外生成 PSD。

确认导入器覆盖范围后，在当前说明中记录可恢复的精简、模板选择、锚点和组件配置。优先复用已有重放方式；确有必要时才使用外部后处理或项目支持的变体，不为本流程强制新增配置文件或脚本。后处理只调整现成工具已生成的 Prefab，不承担切图、从 PSD 组装初始 Prefab、代码模板写出或绑定赋值；需要重新生成或刷新时调用现成工具的同一入口。项目专用脚本放到目标项目入口允许的工具或任务目录，保持在 `Assets` 和其他 Unity 导入范围之外；不放入通用个人 Skill，也不复制进 `Assets` 或为其新增永久菜单、导入回调。沿用项目允许的外部 Editor 自动化按需执行，保留入口、参数与输出说明，便于后续重放。

重新生成前比较当前正式 Prefab 与原说明中的适配参数，补记尚未记录的用户修改并保留可恢复资产。重新生成后，通过当前两份说明和旧正式资产对比当前工具输出，恢复仍适用的精简、模板、锚点、布局及引用配置，再处理本次设计差异。用户最新保存的适配是基线，过时固定参数不能机械写回；不默认采用临时候选加合并的另一套主流程。核对生成器实际覆盖行为，保留正式资源 GUID 和有效引用；现成工具不能安全完成目标输出时，报告具体阻断，不改框架或导入器来绕过。

操作用稳定图层 ID、语义映射或经过校验的路径定位，并检查预期节点类型；匹配不唯一时停止该项，不能按模糊名称删节点。重复执行不得重复添加容器、组件或实例。

至少检查以下实际结果，并按任务范围报告未运行的部分：

- 在基准与选定长宽比中预览，核对关键视觉、边距、遮挡及文字可读性；按 [文本居中与溢出](#文本居中与溢出) 检查固定文案的对齐与显示，仅对动态文本按实际预期验证内容变化及溢出风险，记录证据及未覆盖范围。
- 增减或隐藏显示项，确认布局重排、间距、顺序和尺寸；运行列表覆盖空列表、单项及设计允许的多项，检查隐藏模板不占位。
- 代码生成、必要手写引用修复、编译和刷新后重新加载 Prefab，检查 Mono 类型与序列化引用；涉及运行接入时验证显示、隐藏、重开和 Item 清理。
- 本轮实际重新生成并按 MD 恢复后，比较最终结构、绑定、布局及 GUID/引用与记录基线；这次真实迭代可作为重放验证，不为验收强制额外导出一轮。确需额外重导入测试时先核对覆盖范围和授权，保护共享资源。只提供脚本而未执行重放时明确注明。
