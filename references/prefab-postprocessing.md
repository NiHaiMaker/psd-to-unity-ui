# Prefab 精简与布局

在视觉 Prefab 已生成、需要精简节点绑定、落实 Item 复用或配置适配布局时读取。此阶段处理运行资源；PSD 保留设计与外观参考，除非本次同时要求回写。优先配置 Unity 内置和项目既有组件，不为整理/适配新增自定义 MonoBehaviour、工程内辅助 `.cs` 或永久菜单。完整流程在此阶段完成后继续调用现有绑定生成，完成必要手写引用修复，再编译和刷新。

已有正式 Prefab 或用户适配修订时先读取 [已有链条维护](existing-ui-maintenance.md)：合并前确认改动清单，按变化范围后处理；用户仅改适配时只检查和记录，不适用本节完整重放和绑定顺序。

## 先精简运行职责

为待调整节点记录原定位、用途、保留的视觉、绑定变化及理由。已有面板先检查手写代码、动画和序列化引用；“当前没有显隐调用”不能证明节点无需动态内容或交互。

使用 [阶段溯源记录](traceability.md) 中的第二份模板，在操作前记录刚导出的 Prefab 基线与调整意图，完成后填写实际变化、原因和验证。布局完成及绑定刷新后的 Prefab 指纹分开保留，使说明能够对应具体资产状态。

| 节点职责 | 处理 |
|---|---|
| 始终显示的背景、边框、静态文字 | 保留视觉；无运行访问需求时去绑定标记 |
| 动态文字、图标、进度、点击目标 | 保留对应组件或交互绑定 |
| 纯锚点/布局容器 | 保留层级职责，无代码访问需求时不绑定 |
| 需要整体显隐、移动或播放状态的功能组 | 保留所需组引用；勿把独立控制需求误判为冗余 |
| 可由同一模板表达的重复结构 | 保留一个模板，明确实例数量、数据来源及生命周期 |

绑定精简不等于视觉删除。移除空容器前确认它不承担锚点、蒙版、布局、动画或组件引用，并验证子节点的坐标、缩放与绘制顺序。装饰 Graphic 的 Raycast Target 可在确认不承担点击命中后关闭；不能关掉唯一的交互命中面。

## 模板与实例

先比较字段、组件类型、布局和变化数据，结构不同的控件不强行合并。参考外观的切图、字体和文字需有保留或数据接入方案；只有替代实例方案明确后，才从最终运行 Prefab 移除参考节点。只交付 Prefab 时，可以保留唯一模板并说明显示实例的接入点，不虚构业务列表。

模板可以本身作为首个显示项，也可以隐藏后用于克隆。隐藏模板通常不参与 LayoutGroup 排列；克隆继承隐藏状态时必须显式激活。核对最终父节点、兄弟顺序及模板是否意外占位。运行生成器要求模板先完成 Mono 与引用刷新时，遵循其顺序，不能把普通参考节点当作已绑定实例。PLink 细节见 [通用 Item 判定](plink-integration.md#通用-item-判定)。

## 锚点与布局组件

先确定整体区域与屏幕边缘的关系，再安排区域内部的序列。固定 HUD 使用顶部/底部/侧边锚点；列表内部由布局组件排布，图标上叠加的冷却、文字和特效仍保持相对定位。

| 需求 | 选择与约束 |
|---|---|
| 同级元素从左到右或从上到下排列 | HorizontalLayoutGroup / VerticalLayoutGroup；按设计设置顺序、间距、Padding、Child Alignment |
| 单元需要固定或首选宽高 | LayoutElement；父组开启对应轴的 Child Control Size，按需关闭 Child Force Expand |
| 容器需随内容大小伸缩 | ContentSizeFitter，仅启用需要的轴；确认父布局没有同时控制该轴尺寸 |
| 装饰或模板需要排除出布局计算 | 按用途放到布局容器外、隐藏，或设置 LayoutElement.ignoreLayout；勿将显示实例一并排除 |

同一 RectTransform 的同一轴只由一个系统决定尺寸，位置也只由一个系统驱动。添加布局前检查运行脚本是否写 anchoredPosition/sizeDelta；移除或迁移冲突的控制，不让布局和脚本反复覆盖。固定区域不为“配齐组件”添加 ContentSizeFitter。需要缩放/脉冲效果时通常保持 Child Scale 关闭，或将效果放到单元内部的视觉子节点，避免相邻项随动画抖动。

布局组件无需代码绑定标记；存在明确运行访问需求时，才按项目支持方式暴露引用。参考尺寸、CanvasScaler、根 Canvas 与安全区服从现有运行框架：不要在嵌套 Canvas 上盲目添加第二套缩放或安全区控制。

## 重导入与实际验证

涉及重新导出 PSD 时，先执行 [导出前整理稿检查](psd-preparation.md#导出前整理稿检查)，使用核验后的当前修正版，不能为重导入测试从源重生成来覆盖它。仅对已有 Prefab 重放后处理时不额外生成 PSD。

确认导入器覆盖范围后，将精简、模板选择、锚点和组件配置保存在可重放的外部后处理、配置或项目支持的变体中。后处理只调整现成工具已生成的 Prefab，不承担切图、从 PSD 组装初始 Prefab、代码模板写出或绑定赋值；需要重新生成或刷新时调用现成工具的同一入口。项目专用脚本放到目标项目入口允许的工具或任务目录，保持在 `Assets` 和其他 Unity 导入范围之外；不放入通用个人 Skill，也不复制进 `Assets` 或为其新增永久菜单、导入回调。沿用项目允许的外部 Editor 自动化按需执行，保留入口、参数与输出说明，便于后续重放。

重放前比较正式 Prefab 与原说明中的适配参数；已记录的用户新适配优先，过时的固定参数不能写回正式 Prefab。已有正式资源时，重新导出和重放使用临时候选；只有确认的差异才合并，验证成功后删除临时 Prefab 并保留正式资源依赖。

操作用稳定图层 ID、语义映射或经过校验的路径定位，并检查预期节点类型；匹配不唯一时停止该项，不能按模糊名称删节点。重复执行不得重复添加容器、组件或实例。

至少检查以下实际结果，并按任务范围报告未运行的部分：

- 在基准与选定长宽比中预览，核对关键视觉、边距、遮挡及文字可读性。
- 增减或隐藏显示项，确认布局重排、间距、顺序和尺寸；运行列表覆盖空列表、单项及设计允许的多项，检查隐藏模板不占位。
- 代码生成、必要手写引用修复、编译和刷新后重新加载 Prefab，检查 Mono 类型与序列化引用；涉及运行接入时验证显示、隐藏、重开和 Item 清理。
- 使用现成工具支持的隔离输出或写入范围完整隔离的独立工作副本再次导入并重放后处理，比较最终结构、绑定和布局；已有正式或共享资源时，不能仅因已备份就直接向其重导入。只提供脚本而未执行重放时明确注明。
