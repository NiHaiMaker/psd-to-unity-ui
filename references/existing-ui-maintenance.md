# 已有链条维护

已有源 PSD、整理稿、正式 Prefab 或绑定代码，或用户直接修改整理稿、正式 Prefab 时读取。本文落实用户确认的维护流程，不表示已实现通用自动合并器；执行时按当前导出器、资源引用和实际变化选择操作。

## 识别当前状态

关联源 PSD、整理稿、正式 Prefab、原 `01-PSD修改说明.md` / `02-Prefab减法与布局说明.md`、外部后处理和生成/手写代码。保留当前工作副本改动，明确当前操作针对的是 Prefab 资产、Prefab 编辑阶段还是场景实例；不能把未应用的实例覆盖当成正式资产，也不自动保存无关场景。

同一界面始终维护固定的两份说明，从其中的历史记录、可取得的版本差异和已有快照识别变化；轮次变化只追加记录，不新增同类 MD。SHA-256 只能识别版本变化，参数变化须读取实际结构或已保存的参数记录。没有旧证据时记录当前值和历史未知，不编造旧值。PSD 主要提供视觉和语义结构，正式 Prefab 中的布局组件、适配模式以及用户修正是运行适配的保留依据。

## 整理稿修正后续作

“新一轮从源开始”仅针对源设计更新。用户修正本轮 `_UI.psd` 时，执行 [导出前整理稿检查](psd-preparation.md#导出前整理稿检查)，以修正版继续并更新原第一份说明，不重新生成来覆盖。没有正式 Prefab 时接新建流程；已有正式 Prefab 时接下节第 2 步。新检查和导出追加到本轮记录，旧候选、旧确认范围按实际差异复核，不能把历史导出摘要改成当前 PSD 摘要。通用纠错反馈与单页记录按同一检查入口处理。

## 源 PSD 更新与合并

1. **从源 PSD 开始新一轮。** 使用用户本次提供或链条明确指向的源稿，保留该源，另存新的 `_UI` 整理稿，在固定的第一份说明内追加本轮处理记录；不覆盖上次整理稿，也不新增一套 MD。先按 [整理稿检查](psd-preparation.md#导出前整理稿检查) 中的新源处理要求，只读核对旧整理稿并补录尚未记录的修改，再参考原第一份说明保留仍适用的意图，记录本轮处理。来源或新设计与旧修正冲突时先查证，无法判断再询问具体问题。
2. **检查整理稿并另外生成临时 Prefab。** 先完成 [导出前整理稿检查](psd-preparation.md#导出前整理稿检查)。使用现成导出工具的同一入口及其支持的隔离配置或写入范围完整隔离的独立工作副本，核对本次临时输出路径；正式 Prefab 保持可用。切图和其他会写入的导出资源也控制到隔离范围，已有共用资源仅只读复用，避免尚未确认的候选导出改掉正式外观。不能靠文件名变化、仅复制 PSD 或导入器覆盖弹窗判断隔离成功。若现成工具无法隔离，说明该阶段限制，不自行拼接底层服务、复制工程设置重定向输出、覆盖共享全局配置或生成替代 Prefab。
3. **形成可审阅的改动清单。** 比较候选与当前正式 Prefab，逐项写清节点复制/新增/删除/替换、需补充的减法、布局和适配、原因、应保留的用户设置、受影响的绑定与功能代码。包含图片的复用依据、缺失/变化图片及共享引用影响；同名图片不能直接判为复用。能通过图片和参数对照说明的直接给出证据。记录比较时的资产版本与关键字段依据，将清单追加到固定第二份说明的本轮记录中，等待用户确认后才改正式 Prefab 或正式资源。
4. **复核后按清单合并。** 开始正式写入前先执行下述 [正式写入前复核](#正式写入前复核)。将候选中对应节点的必要变化复制或修改到正式 Prefab。优先更新已有对象的必要字段；保留布局控制的尺寸/位置、既有组件和引用。只对新增或变化节点做减法及布局适配，不重新执行一套固定后处理覆盖整个正式面板。节点身份不明确、同名或同一属性有冲突时核对证据；无法确定的部分单独说明。
5. **每次合并都走现有绑定工具。** 在正式 Prefab 上用现有工具生成绑定，按新字段和类型修复本次变化影响的手写引用，待编译通过且生成类型可加载后刷新引用，再重新加载检查。节点更名、删除或类型变化造成的必要修复不能等到绑定通过后才做；无此类变化则直接进入编译检查。不手改生成文件，已确认范围内的必要修复不二次询问。工具刷新自身可能调整根 Canvas/Transform，因此还要核对用户适配是否保持。
6. **按确认范围完成其余功能。** 必要引用修复已在编译前完成；继续保留已有行为，落实清单中其余具体功能。确认 Prefab 改动后，不为清单内代码再次提问。出现新需求或原清单未涵盖的影响时说明新增范围，不能把一次确认当作任意改动授权。
7. **验证并清理。** 正式 Prefab 合并、绑定和相关显示检查成功后，删除本次临时 Prefab，只交付正式 Prefab。先确认正式资源没有指向临时 Prefab/其中对象的引用；图片、字体、材质等已被正式 Prefab 使用的资源继续保留，仅在用户明确要求且已纳入确认范围时迁移并维护引用，记录工具原始输出位置与迁移后位置，其余依赖原位保留，不能整目录盲删。仅清理本次创建的临时对象和空目录；失败时保留恢复所需内容并报告，未完成前不假报清理成功。

Unity 操作始终通过项目规定通道，PLink 项目使用 Coplay MCP；外部自动化留在 Unity 导入范围外。删除临时资产遵守已授权范围与版本控制约束，不进行未授权的 SVN 调度。

## 正式写入前复核

正式 Prefab 的合并、重建及已列清单的调整，在实际写入前复核；等待用户确认或中断后恢复时也适用。该检查沿用现有读取能力，不新增工程内脚本或固定审批点。

- 形成清单时，在第二份说明保存正式 Prefab、临时候选及本次待改或依赖的图片/材质等资产的版本和定位证据，包含相关 `.meta` / GUID、影响判断的字段或内容。范围限于本次改动与依赖，不扫描整个工程。摘要用于发现变化，原值和具体差异依靠结构记录、参数或可用快照。
- 正式写入前重新读取这些对象，与清单形成时的状态比较；尚无正式资产时核对目标仍未被其他产物占用。检查候选仍对应已核验的 PSD 版本及导出配置，源版本变化按 [整理稿检查](psd-preparation.md#导出前整理稿检查) 重新处理，不能直接应用过时的候选。
- 无变化则按原确认执行。有变化先查明实际字段和引用影响，保留与本次改动无冲突的用户新设置，更新记录后继续原确认范围。只有新增冲突、变更范围扩大或需要转为重建时，才补充相应清单并取得所需确认；不能只因摘要不同就全部重问，也不能把旧确认当作覆盖用户新设置的授权。
- 在原第二份说明追加复核时间、当前版本、差异、保留项及处理结果；适配变化同时维护用户适配修订。缺少旧证据时重新形成可核实的比较依据，不编造“基线未变”。只检查已改适配或仅改手写功能代码时，不因本节额外修改 Prefab。

## 改动较多时重建

由 Agent 根据结构变化、旧布局复用程度、引用迁移风险和合并成本判断是否建议重建，不机械设置节点数量阈值。

需要重建时，在正式写入前列明原因、重建范围、需要补回的布局/适配与组件、引用和功能影响，明确询问用户。用户确认重建后再执行；可以在同一份正式改动清单中一并确认，已明确批准的重建和代码不重复询问。原先只批准合并时，不能静默转为重建。

重建前同样执行 [正式写入前复核](#正式写入前复核)，沿用正式 Prefab 的名称和路径，继续作为同一个界面使用。保留可恢复的原资产和引用信息，维护原 `.meta` / GUID，核对内部对象引用、生成字段、外部序列化引用、动画路径及已有实例/Variant 覆盖。同名同路径不保证所有节点身份或引用自动保留，实际失效项必须修复或明确报告。验证后删除临时 Prefab，不留下另一个竞争使用的正式版本。

## 用户直接修改适配

用户修改并保存正式 Prefab 的布局组件、适配模式、锚点或相关参数后，以其新设置为最新方案，不将它恢复为旧自动适配，也不从 PSD 重建来覆盖它。

1. 读取当前正式资产，与原第二份说明及可用基线比较，识别实际变化的节点、组件、控制方式和参数。原因未知时写“用户调整，原因未说明”，不替用户推断设计意图。
2. 检查显示、边距和布局控制关系，按变化范围验证必要尺寸；涉及文字时按 [文本居中与溢出](prefab-postprocessing.md#文本居中与溢出) 核对固定文案的对齐与显示，仅对动态文本按业务预期检查内容变化及溢出风险。如果发现新适配存在问题，先说明并列出建议，不自动撤销用户调整。
3. 在**原 `02-Prefab减法与布局说明.md`** 追加“用户适配修订”：记录原值（可核实时）、新值、影响、保存后摘要与实际验证；原有历史指纹保留，当前适配摘要以最新设置为准。不为一次用户适配修正另建重复说明。
4. 仅适配变化且绑定节点身份、名称、组件类型和 Item 作用域未变化时，不重新导出、不运行绑定工具、不修改功能代码。若实际还包含绑定结构变化，列出必要处理清单，再按已确认范围处理。
5. 后续 PSD 合并先读取最新适配记录。外部后处理含旧固定参数时，先根据当前记录准备更新并纳入下次执行方案，不能先重放旧脚本再修回。用户适配记录是后续保留依据，不能因脚本仍旧就认定用户设置错误。

仅维护记录和验证用户已完成的适配，不触发“修改正式 Prefab 前”的确认步骤，因为没有新增正式资产修改。缺少原说明时可以建立首份记录并注明历史未知；不能声称已还原上次适配过程。

用户委托 Agent 调整适配、尚未实际完成时，先完成局部变更清单并核对已有确认，再落实具体调整、验证和原说明修订；已有明确确认或用户要求直接执行的范围不重复询问。不要把这类请求误判为只需观察。若只是非合并的纯适配参数调整且绑定结构不变，同样无需重跑绑定。

## 仅修改手写功能代码

用户只要求修改点击逻辑、显示数据或其他手写功能，且现有节点、组件、Item 作用域与序列化绑定仍满足需求时，只读核实现有引用与调用链，然后按已明确需求修改手写代码、编译并验证相应行为。有效的现有绑定无需重新生成或刷新，也不导出 PSD、不调整 Prefab、不要求确认空的 Prefab 改动清单。

实际发现所需字段缺失、节点/组件需要变化或必须修改正式资源时，列出这些具体变化及功能影响，按已有授权进入相应流程；不手改生成文件或添加按名称查找的兜底。纯功能任务的验证与记录遵守项目要求；无需新建 PSD/Prefab 说明，可在已有第二份的相关功能记录中追加结果，未执行的导出/绑定不写成已完成。

## 记录与交付

源 PSD 更新、整理稿人工修正和重新导出都在同一对固定说明中追加记录，关联其中此前的记录编号，不按轮次新建 MD。第二份保存候选路径、用户确认范围、合并或重建决策、必要手写引用修复、正式各阶段摘要及临时清理结果；当前正式状态与待合并候选分别标明。用户适配修正追加到这同一份第二说明，并更新受影响的待合并比较依据，保留原清单历史。模板见 [阶段溯源记录](traceability.md)。只报告实际运行的导出、绑定、编译、显示与功能检查，不将说明更新当成资产或工具验证通过。
